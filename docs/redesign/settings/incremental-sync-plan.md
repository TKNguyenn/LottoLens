# Incremental retained history and per-game Windows schedules

User request (2026-11-11): update only new draws, retain latest configured N per game by removing older active history; add per-game daily switches. User clarified jobs must run with LottoLens closed and each game needs its own time. This expressly supersedes earlier storage/network freeze only for this synchronization/scheduling feature; tests/main.py/AI/math remain unchanged.

Chosen approach: incremental source traversal plus atomic add/prune in SQLite; Windows Task Scheduler daily interactive-user tasks, one per game/profile, disabled by default. Times are Vietnam UTC+7. Computer must be on and user logged in. No catch-up/restart-on-failure; failed daily attempt is recorded once/day. Background helper reads persisted preferences and never imports/uses AI. StartWhenAvailable=false; app opening does not issue a network request.

History safety: do not prune on failure/cancel/incomplete/unknown receipt. Keep saved suggestions/reports/snapshots, prune all revisions only for out-of-window active draw IDs in the relevant game/mode/rule scope. Add/prune/continuity proof are one transaction. Existing two-argument add_draws remains additive for CSV/legacy callers. A retained-window fingerprint proves continuity for incremental stop-at-known; missing/invalid proof or increasing N causes a full bounded fill. Initial HTML/page may include already-stored rows; cannot avoid reading the source head/overlap page.

Contracts for parallel work:
- Source: `OfficialSource.fetch_history(rule, limit, cancel=..., progress=..., known_draws=())`; unchanged default behavior; known_draws is a proven retained window. Complete receipt statuses requested_limit/source_boundary/known_boundary.
- Store: `sync_window(rule, limit)` returns proven stored draws or[]; `add_draws(rule, draws, *, keep_latest=None, check_cancel=None)` atomic optional cap/proof; `apply_sync(rule, receipt, limit, check_cancel=None)` guards incomplete and only prunes for complete statuses, legacy partial adds without prune. `apply_sync_many(batches,limit,check_cancel=None)` commits all Keno projections together; callbacks raise to cancel. `claim_auto_update(game_id, day)->bool`, `finish_auto_update(game_id, day, status, message)`, `auto_update_runs()->list[dict]` (game_id,day,status,message). Additive schema tables, preserve current user_version and old APIs.
- Preferences: `auto_updates={game:{enabled:false,time:'20:00'}}`, backward-compatible old preferences; enabled bool and HH:MM validation, 7 games. Save is opt-in; no tasks or requests for all-default-off.
- Scheduler: new `app/scheduling.py::configure_schedules(preferences, db_path, preferences_path, previous_preferences)` called only on explicit Save; create/update/delete own pref-profile-hashed tasks via native schtasks/XML, refresh enabled jobs, return undo callback holding original task XML for preference-write rollback; no credentials/API keys. `app/scheduled_sync.py::run_scheduled(game_id,db_path,preferences_path,now=None)->int`; CLI `scripts/scheduled_sync.py`; source/store APIs above. Run only if enabled, claim Vietnam day before network, record success/failure, no retry. Keno fetch once and atomically persist validated results for all10 pick modes; one daily claim per game.
